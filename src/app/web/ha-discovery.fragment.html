🏠 Home Assistant

Two independent integration paths — use either, both, or neither.

How It Connects

The device talks to Home Assistant over two separate paths. They do not depend on each other, and each can be enabled on its own.

PathDirectionWhat it needsWhat it gives you
Service Actions
(REST API)		 device → HA HA URL + token
(set below)		 The Home Assistant Service button action — call any HA service (lights, scenes, covers…).
MQTT device ↔ HA MQTT broker
(set on the MQTT page)		 Auto-discovery, live HA state, [mqtt:…] bindings, and remote control — see below.

Service Actions use Home Assistant's HTTP API and need no MQTT broker. Everything in the MQTT section below needs only a connected broker — no token.

Service Actions (REST API)

Configure a Home Assistant URL and long-lived access token to enable the Home Assistant Service button action, which calls any HA service (lights, switches, covers, scenes, etc.). This path is independent of MQTT.

Base URL including scheme and port. HTTPS is supported (certificate not verified). Leave empty to disable service actions.
Create one in Home Assistant under your profile → Security → Long-lived access tokens. Tokens longer than 183 characters are truncated.
MQTT Capabilities

Connect an MQTT broker on the MQTT page first. Once connected, the capabilities below become available. Each is independent — you can use any subset.

Auto-Discovery & State — device → HA

The device automatically advertises its data and capabilities to Home Assistant — sensors, diagnostics, buttons, siren, volume, and other entities appear under the homeassistant/ topic prefix with no manual YAML, and the device keeps publishing their live values. Just make sure HA's MQTT integration is enabled.

Live HA State via Statestream — HA → device

Auto-discovery sends data to Home Assistant. To go the other way — bring live HA entity state onto the device — enable HA's mqtt_statestream integration, which publishes every entity's state to MQTT. Add this to your HA configuration.yaml:

mqtt_statestream:
  base_topic: homeassistant
  publish_attributes: false
  publish_timestamps: false

See the MQTT Statestream documentation for details.

[mqtt:…] Bindings — any topic → device

Button labels, colors, and widgets can subscribe to any MQTT topic — HA Statestream above, or any other publisher on your broker — to show live data. For example, bind a button to a light's on/off state:

[mqtt:homeassistant/light/living_room/state;;]

Configure these in the Pad Editor. Bindings work without auto-discovery or Statestream — they only need the topic to exist on the broker.

Remote Control — HA → device

Auto-discovery also exposes control entities so Home Assistant can drive the device: a screen-select entity for remote navigation, screensaver wake, notification messages, camera snapshot buttons, and (on audio boards) siren, volume, and beep buttons.

MJPEG Camera

On camera-capable boards, add Home Assistant's MJPEG IP Camera integration manually. Use these URLs, replacing <device-ip> with this device's address:

MJPEG URL: http://<device-ip>/api/camera/stream
Still image URL: http://<device-ip>/api/camera/snapshot.jpg

When portal Basic Authentication is enabled, enter the same username and password in Home Assistant. Do not enable stream preloading: this device limits concurrent MJPEG clients.
