🏠 Home Assistant

REST API connection for service actions and MQTT auto-discovery.

Service Actions (REST API)

Configure a Home Assistant URL and long-lived access token to enable the Home Assistant Service button action, which calls any HA service (lights, switches, covers, scenes, etc.).

Base URL including scheme and port. HTTPS is supported (certificate not verified). Leave empty to disable service actions.
Create one in Home Assistant under your profile → Security → Long-lived access tokens. Tokens longer than 183 characters are truncated.

MQTT Auto-Discovery

When MQTT is configured, the device automatically advertises its data and capabilities to Home Assistant — sensors, buttons, siren, volume, and other entities appear under the homeassistant/ topic prefix with no manual YAML. This makes the device ready to use in HA dashboards and automations out of the box.

Just make sure your MQTT broker is reachable and HA's MQTT integration is enabled.

Live HA State via MQTT Statestream (optional)

Auto-discovery sends the device's data to Home Assistant. To go the other way — show live HA entity state on the device — enable HA's mqtt_statestream integration. It publishes every entity's state to MQTT, so you can, for example, bind a light's on/off state to the color of a button icon.

Add this to your HA configuration.yaml:

mqtt_statestream:
  base_topic: homeassistant
  publish_attributes: false
  publish_timestamps: false

Then a button label or color can reference live state with a binding like:

[mqtt:homeassistant/light/living_room/state;;]

See the MQTT Statestream documentation for details.
