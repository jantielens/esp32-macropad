Rendering
The selected mode is used after the next restart. Refresh settings apply to both modes.
Threshold uses a brightness cutoff to choose black or white. Dithering simulates gray with patterns of black and white pixels: Bayer uses a repeating 4x4 grid; Blue noise uses a less regular pattern.
Pixels at or above this level become white; the rest become black. Higher levels make the image darker.
Refresh Settings
How often idle data bindings are checked. Higher values reduce background checks and can reduce panel updates. On supporting devices, user-triggered local-variable changes refresh bindings without this wait.
Delay after a completed presentation before another background update can start. Higher values combine rapid changes and reduce panel work. Devices supporting interaction priority can bypass this delay for navigation, dialogs and changed local-variable actions; active panel work still finishes first. Other devices apply this interval to interactive updates too.
Run a full refresh after this many successful partial updates. Depending on the driver, a partial update may cover a region or use a partial waveform across the panel. Set 0 to disable count-based cleanup, not startup, recovery or manual full refreshes. Modes that always use full refreshes ignore this threshold.
Rechecks visible time bindings when the minute changes, even between passive binding checks. Panel scheduling and an active refresh can delay the visible update.
VCOM (advanced)
Enter the negative voltage specified on your panel, for example -1.530. An incorrect voltage can degrade image quality. Only drivers that support configurable VCOM use this setting; other drivers ignore it. Changes take effect after restart. This does not program calibration EEPROM.
0 uses the current board default; it is never applied as a voltage.
