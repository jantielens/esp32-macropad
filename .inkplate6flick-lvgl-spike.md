## Scope and Current Status

This spike evaluates an always-on LVGL interface for the Soldered Inkplate
6FLICK. The board target combines the device's 1024 x 758 e-paper panel with
the existing pad-oriented firmware: 3-bit grayscale with full waveforms and
1-bit black-and-white with partial updates. It is intentionally separate from
the existing duty-cycled Inkplate target.

The experimental target builds successfully with a light LVGL theme, touch
input, buffered rendering, and e-paper-specific interaction policies. It
occupies 96% of the available 3 MB no-OTA application partition.

## Changes by Feature

### Experimental LVGL Board Support

* Added experimental grayscale and B/W Inkplate 6FLICK LVGL board targets,
  board metadata, and build selection.
* Added display and touch driver selectors for the Inkplate backend.
* Added an Inkplate display HAL that accepts LVGL RGB565 flushes, converts each
  pixel to one of eight grayscale levels, and writes it to the Inkplate
  framebuffer.
* Added a Cypress touchscreen HAL that shares the display-owned Inkplate
  instance and forwards the primary touch coordinate to LVGL.
* Selected a light LVGL theme, a compact render buffer, no backlight support,
  no audio or BLE features, and a 3 MB no-OTA partition for the experiment.
* Disabled the unused TJPGD decoder on both targets to avoid unnecessary code
  size and memory pressure.

### Display Task and Refresh Coordination

* Used buffered display presentation so LVGL can continue processing input
  while the e-paper backend performs a slow panel waveform.
* Kept the first invalidated frame pending until the buffered presentation task
  is ready to consume it, avoiding a lost initial display update during boot.
* Added board-selectable task-stack placement. Inkplate uses internal RAM
  stacks because its classic ESP32 FreeRTOS port does not accept externally
  allocated static task stacks.
* Enforced a minimum interval between Inkplate full refreshes and added a
  resettable settle period after the last framebuffer change. This coalesces
  closely spaced LVGL updates into one useful panel update.
* Added a PSRAM framebuffer snapshot to suppress panel updates when LVGL has
  invalidated the screen but the final mode-specific framebuffer is unchanged.
* Added refresh diagnostics for full presentations, B/W partial-update
  requests, and skipped no-op updates.
* Added `INKPLATE_LVGL_DEFAULT_MODE`. The single `inkplate6flick-lvgl` board
  target defaults to B/W and can persist grayscale mode through the portal for
  the next boot.
* B/W mode uses a stable 4x4 Bayer dither of RGB565 luminance, preserving
  anti-aliased font edges as black-and-white coverage. It writes the Inkplate
  black bit for samples below the local dither threshold. Its first frame uses
  a full update, then it uses 1-bit partial updates with a full-refresh
  threshold of 10.
* Moved B/W full-refresh cadence into the driver. The Inkplate library treats
  a nonzero `setFullUpdateThreshold()` value as a command to block partial
  waveforms, so calling it for each frame caused every changed frame to use a
  full waveform.

### Binding Refresh Scheduling

* Added `DISPLAY_BINDING_REFRESH_INTERVAL_MS`, which defaults to `0` for
  ordinary displays and is set to one second for the Inkplate target.
* Aligned passive binding updates to wall-clock interval boundaries after NTP
  synchronization, rather than measuring the interval from the last pad
  update. This keeps arbitrary intervals stable across pad navigation.
* Detected pads containing `[time:]` bindings, including named pad bindings,
  and refreshed them at each minute boundary even when that boundary does not
  coincide with the passive interval.
* Refreshed active pads immediately when NTP becomes valid so time bindings do
  not retain the `--:--` placeholder until the next scheduled update.
* Kept initial pad entry and configuration rebuilds immediate. Tap and action
  handling remain outside the passive binding cadence.
* Added the `HAS_EPAPER_PRESENTATION` capability for persisted E-paper
  presentation settings. Panel mode is selected only during boot; each mode
  has independent binding and presentation intervals, clock-minute refreshes
  can be disabled, and the B/W full-refresh threshold applies live. A
  threshold of zero disables scheduled B/W full refreshes and carries a
  visible ghosting warning in the portal.
* Added a dedicated E-paper Presentation portal page. It ships only with
  `HAS_EPAPER_PRESENTATION`, shows controls for the selected mode, and keeps
  its HTML and JavaScript out of other firmware variants.
* Added the `display_refresh` action, presented to authors as **E-paper full
  refresh**, with `mode: "full"`. It is available only with
  `HAS_EPAPER_PRESENTATION`; portal commands queue it and return immediately,
  while pad actions, MCP, and automation use the same ActionType contract.

### Pad Configuration Lifetime and PSRAM Pressure

* Replaced fixed-size copied pad configurations with dynamically sized,
  immutable cache snapshots.
* Allocated configuration storage PSRAM-first, with an internal-memory fallback
  when required.
* Added reference counting so a cache replacement or delete cannot free a pad
  configuration while a screen, MCP request, or data-stream reader still uses
  it.
* Resized configuration storage when inherited template buttons are merged,
  then trimmed unused capacity after the merge.
* Removed the old cache-transaction layer and its test because cache lifetime
  is now handled directly by acquire, release, and replacement operations.
* Moved the data-stream registry to PSRAM-first dynamic storage and added null
  guards for allocation failure paths.
* Updated MCP pad enumeration to read the immutable cache rather than allocate
  and parse a full configuration for each request.

### Icon Safety, Rendering, and Cache Lifetime

* Added a board-overridable maximum PNG dimension. Inkplate limits each source
  icon dimension to 128 pixels.
* Validated PNG IHDR dimensions before decoding on both file load and upload.
  This blocks malformed or oversized images before an RGBA decoder allocation
  can exhaust PSRAM.
* Published the device icon limit through the device-information API. The Pad
  editor reads that value and rasterizes semantic icons at the device limit.
* Scaled capped source icons at render time when a button needs a larger visual
  icon. This preserves the intended UI size without increasing stored or
  decoded image dimensions.
* Added retirement handling for replaced icon draw buffers. Old buffers remain
  valid until the LVGL objects that reference them are removed, then are
  collected safely. This stopped the repeated pad-save PSRAM decline.

### Useful First E-Paper Frame

* Refactored pad live-data polling so it runs immediately after rebuilding pad
  tiles, as well as during ordinary periodic updates.
* Resolved button state, MQTT, color, numeric, pad-binding, and image-frame
  data before the first new pad frame is flushed.
* Prevented an otherwise expensive full waveform that only showed temporary
  placeholder values such as `---`.

### Unified Slow-Refresh Animation Policy

* Added `DISPLAY_DISABLE_ANIMATIONS`, which defaults to `false` for ordinary
  displays and is enabled by the Inkplate board.
* Suppressed transient tap and pad-action flashes when the policy is enabled.
* Made notification bubbles appear and dismiss directly rather than fade.
  Their duration and tap-to-dismiss behavior remain intact.
* Made visual alerts render as steady overlays instead of fading, blinking, or
  breathing. Their action, duration, and dismissal behavior remain intact.
* Applied gauge and bar-chart updates directly rather than interpolate them.
* Left the policy deliberately narrow: it removes visual transitions that would
  otherwise create extra e-paper waveforms, not functional timers, actions, or
  input processing.

### Partial-Update Assessment

* Verified the installed Inkplate 6 driver only supports `partialUpdate()` in
  1-bit black-and-white mode. It returns without updating the panel in 3-bit
  grayscale mode.
* The library's partial path is framebuffer-differential rather than a
  caller-supplied rectangle API. It compares the full 1-bit framebuffer and
  still requires periodic full black-and-white updates to control ghosting.
* The B/W target uses the library's 1-bit desired framebuffer for no-op
  suppression, so an unchanged LVGL framebuffer never reaches the panel.
* Persisted presentation settings choose the mode at boot. Live mode switching
  remains out of scope because it needs a full visual reset.

### Diagnostics, Documentation, and Tests

* Extended allocation-failure telemetry with free and largest-block PSRAM
  measurements, making fragmentation and allocation pressure diagnosable from
  device logs.
* Added a host test for the dynamically sized pad configuration layout and
  removed the obsolete cache-transaction test.
* Updated the board inventory, compile-time flag reference, driver table, and
  web-portal API documentation for the new target and icon dimension contract.

## Lessons Learned

* Compressed PNG size is not a meaningful safety bound for a decoder. The IHDR
  width and height must be validated before decoding because decode memory is
  driven by raster dimensions.
* Slow grayscale e-paper is a presentation boundary, not an LVGL update-rate
  problem. LVGL may update often, but the panel should receive only final,
  useful states.
* A fixed passive binding cadence needs clock-specific deadlines. A minute
  clock must update on the minute boundary even when a separate MQTT cadence
  is not due.
* Framebuffer equality is the final authority for a physical refresh. A dirty
  LVGL frame does not necessarily represent a visible grayscale change.
* The Inkplate library's partial-update API is black-and-white only. Moving to
  a partial-update mode would be a different visual contract, not an
  acceleration of the existing grayscale UI.
* Ordered dithering preserves LVGL's anti-aliased font edges without a second
  framebuffer or per-frame error-diffusion state.
* The existing buffered presenter was already event-driven. The perceived
  refresh delay came primarily from intermediate invalidations and the full
  waveform limit, not from a blind periodic panel scheduler.
* Full-screen or temporary visual effects are particularly costly on e-paper.
  A single board-level policy is safer and clearer than a growing set of
  feature-specific exceptions.
* Immutable configuration snapshots with explicit reader ownership are easier
  to reason about than copied fixed-size structures. They also avoid reserving
  peak memory for every pad regardless of its actual button count.
* An icon cache must account for LVGL object ownership. Releasing a draw buffer
  at replacement time is unsafe when an old image object may still draw it.
* Source-image caps and render-time scaling provide a practical compromise:
  bounded decode memory without forcing small on-screen icons.

## What Went Well

* The existing display HAL and buffered-present abstraction accepted the new
  e-paper backend without a broad rendering redesign.
* Runtime repeated-save observations stabilized near 2.48 MB free PSRAM after
  the icon retirement fix, indicating the observed decline was addressed.
* The focused e-paper changes retained normal-display behavior. The animation
  policy is opt-in per board, and the common board still builds with animations
  enabled.
* Building the constrained Inkplate target caught integration issues across the
  new conditional-compilation paths.
* The first-frame binding change avoids an entire class of visibly poor e-paper
  updates rather than attempting to hide them after they are already queued.
* Hardware logs confirmed that a clock pad refreshes at the next real minute
  boundary after NTP synchronization, even when that boundary arrives sooner
  than the passive 60-second cadence.

## What Did Not Go Well

* The first implementation path exposed several unrelated-looking symptoms:
  icon decode failures, repeated-save PSRAM loss, placeholder bindings, and
  delayed refresh. They had different causes, so diagnosis required tracing
  allocation ownership and display scheduling separately.
* The experimental firmware is close to the partition limit. At 96% program
  storage usage, new features or libraries need deliberate size review before
  they are enabled for this board.
* Full grayscale waveforms remain inherently slow. Coalescing and removing
  animation frames improve usefulness, but they cannot make the panel behave
  like an LCD.
* The experiment has no hardware-driven automated test for waveform quality,
  ghosting, touch calibration, or long-duration memory behavior. Build success
  is necessary but insufficient evidence for final support.

## Remaining Validation

* Exercise repeated pad saves, icon replacement, and icon deletion on physical
  hardware while recording free and largest-block PSRAM over an extended run.
* Measure perceived latency and ghosting at the selected refresh interval and
  settle delay, then tune those board overrides if needed.
* Verify touch coordinates and rotation across the full panel, including edge
  taps and gestures.
* Test notifications, visual alerts, gauges, bar charts, and first pad entry on
  hardware to confirm that only final states trigger meaningful waveforms.
* Collect refresh and no-op-skip counters during an extended active-pad run to
  quantify how often LVGL invalidations are eliminated before reaching the
  panel.
* Measure B/W partial-update latency and ghosting at the one-second passive
  binding cadence and 10-update full-refresh threshold.
* Review flash growth before enabling additional features. The current target
  has only a small application-size margin.
